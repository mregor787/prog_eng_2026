**Выполнил:** Белоусов Е.Л., группа М8О-107СВ-25

## Вариант задания

### #6 Сервис доставки
Приложение должно содержать следующие данные: 
- Пользователь (User)
- Посылка (Parcel)
- Доставка (Delivery)

Реализовать API: 
- Создание нового пользователя 
- Поиск пользователя по логину 
- Поиск пользователя по маске имя и фамилии 
- Создание посылки 
- Получение посылок пользователя 
- Создание доставки от пользователя к пользователю 
- Получение информации о доставке по получателю 
- Получение информации о доставке по отправителю

## Описание проекта

В ходе данной ЛР в приложение была интегрирована NoSQL база данных MongoDB. В нее было решено перенести сущность **User**. Две другие сущности (**Parcel** и **Delivery**) было решено оставить в реляционной базе данных PostgreSQL, поскольку они требуют строгой консистентности, транзакционности и активно используют реляционные связи. 

### Было реализовано

- Интеграция API микросервиса **user-service** с MongoDB с помощью компонента `userver::components::Mongo`;
- В файле `schema_design.md` описана документная модель для коллекции `users` с обоснованием выбора embedded/references;
- В файле `data.js` содержатся тестовые данные для коллекции `users`;
- В файле `queries.js` написаны MongoDB-запросы для всех операций;
- В файле `validation.js` описана валидация схемы для коллекции `users`.

## Запуск проекта

### Запуск файлов для тестирования

Запускать файлы `data.js`, `queries.js`, `validation.js` можно с помощью команды:

```
mongosh delivery_db data.js
```

Но сначала надо подключиться к MongoDB:

```
docker exec -it delivery-mongodb mongosh -u delivery_mongo -p delivery_mongo_password --authenticationDatabase admin delivery_db
```

### Требования

* Docker
* Docker Compose

### Сборка и запуск

```bash
docker compose build --no-cache
docker compose up
```

Сервис будет доступен по адресу:

```
http://localhost:8080
```
