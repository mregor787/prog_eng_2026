# Лабораторная работа №5 "Оптимизация производительности через кеширование и rate limiting"

**Выполнил:** Белоусов Е.Л., группа М8О-107СВ-25

## Вариант задания

### #6 Сервис доставки
Приложение должно содержать следующие данные: 
- Пользователь (User)
- Посылка (Parcel)
- Доставка (Delivery)

Реализовать API: 
- Создание нового пользователя 
- Поиск пользователя по логину 
- Поиск пользователя по маске имя и фамилии 
- Создание посылки 
- Получение посылок пользователя 
- Создание доставки от пользователя к пользователю 
- Получение информации о доставке по получателю 
- Получение информации о доставке по отправителю

## Описание проекта

В ходе данной ЛР в приложение был интегрирован Redis для кэширования данных, а также создан Rate Limiter. 

### Было реализовано

#### Кэширование (Cache-Aside)

- **`GET /api/v1/parcels` (parcel-service)** - кэшируется на 60 секунд (ключ `parcels:user:{user_id}`). Инвалидируется явно при создании новой посылки.
- **`GET /api/v1/deliveries?sender_id=...` (delivery-service)** - кэшируется на 60 секунд (ключ `deliveries:sender:{sender_id}`). Инвалидируется явно при создании новой доставки.
- **`GET /api/v1/deliveries?receiver_id=...` (delivery-service)** - кэшируется на 60 секунд (ключ `deliveries:receiver:{receiver_id}`). Инвалидируется явно при создании новой доставки.

#### Rate Limiting (Fixed Window Counter)

Реализован алгоритм Fixed Window Counter с атомарными операциями INCR и EXPIRE через Redis. Возвращает статус `429 Too Many Requests` и заголовки `X-RateLimit-*`.

- **`POST /api/v1/auth/login` (user-service)** - 10 запросов в минуту (по IP).

Подробная архитектура описана в [performance_design.md](performance_design.md).
